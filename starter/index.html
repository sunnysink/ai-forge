Claude Code Starter

Give Claude a permanent memory of your business, so you stop re-explaining yourself every single time you open a new chat.

Runs in your browser. Nothing to install. You will not write code.

What you'll have at the end

A folder your assistant actually reads

Right now, everything Claude knows about your business lives inside one conversation. Close the tab and it's gone. You paste your voice, your offers, and your ideal client back in every time, and you have gotten very good at it, which is the sad part.

By the end of this guide you'll have a private folder holding your brand voice, your offers, and your client notes, and an assistant that opens it before answering you. A filing cabinet instead of a sticky note.

Read this before you start, so nothing surprises you four steps in.

You'll need a Claude plan at Pro or above. Claude Code in the browser isn't available on the free plan. If you're on free right now, everything below still makes sense to read, and you'll need to upgrade before Step 3 will work.

You'll need a GitHub account, which is free to make.

Time: about 20 minutes, and most of that is waiting on signups.
Step One

Get a GitHub account

GitHub is where your folder is going to live. Think of it as a filing cabinet that sits online instead of on your desk, so it's there whether you're on your laptop, your phone, or someone else's computer.

  • Go to github.com/signup
  • Use whatever email you actually check
  • Slow down on the username. Read the box below before you pick it.
Your username becomes part of every public link you ever make here.
Anything you publish from GitHub gets an address built out of it: yourname.github.io/the-thing/. Every artifact, tracker, quiz, and client tool you build carries that name in the link, and the only way around it is buying a domain and pointing it there each separate time.

So pick it the way you'd pick a business email. Your business name or your own name both work beautifully. The handle you made in 2009 is going to look strange in a link you send a paying client.
Already have an account? Look at the username. If you'd be glad for a client to see it in a link, keep it. If you'd wince, make a new one now while it costs you nothing.
Step Two

Make your filing cabinet

In GitHub, a filing cabinet is called a repository. Ugly word, simple thing. It's a folder that can hold other folders.

  • Go to github.com/new
  • Name it biz-brain, lowercase, with the hyphen
  • Click Private. This matters. Your client notes and your offers are in here.
  • Tick Add a README file
  • Click Create repository
Do not skip Private. Public means anyone on the internet can read it, including people who found it by accident. Private means you and whoever you invite. If you clicked past it, open Settings on the repo and change it now.
Step Three

Install the Claude app on your GitHub

Read the step title again, because the word install is doing all the work here. Signing in with GitHub is not the same as installing the app, and only one of them lets Claude see your files.

  • Go to claude.ai/code and sign in with your Claude account
  • It prompts you to connect GitHub. Follow that prompt all the way through to the install screen. Stopping at the sign-in leaves you with an empty repository list and no explanation.
  • GitHub asks which account to install on. Pick the one that owns biz-brain.
  • GitHub asks which repositories. Choose All repositories, or Only select repositories and pick biz-brain.
  • Click Install

You'll then be asked to create a cloud environment. The defaults are right for this. Give it any name and click Create environment.

Back at claude.ai/code, click the repository selector under the message box and choose biz-brain.

This is the step that needs Pro. If you're on the free plan you'll get stopped here, and it's the plan, not anything you did wrong.

No repositories in the list?

This is the most common wall, and it almost always means the app got authorized but never actually installed. Install it directly:

  • github.com/apps/claude/installations/new

Choose the account that owns your repo, choose All repositories or select biz-brain, click Install, then reload claude.ai/code. Your repo will be there.

A private repo is not the problem. Private works exactly like public here, as long as the app is installed on the account that owns it.
Don't ask Claude to fix a connection problem. Claude can't install a GitHub app or change your plan from inside a conversation. It will sound like it's helping, and nothing will move. This one is yours to click.
Buttons move around as things get updated. If a label reads a little differently than what's written here, you're still in the right place. Look for the word connect or repository and follow it.
Step Four

The Filing Cabinet Prompt

Paste this straight in. Nothing to fill out first, and it won't ask you any questions. You're building the empty cabinet here. Filling the drawers comes after.

Set up my business brain in this repo. Create exactly this structure, with these exact names: CLAUDE.md README.md first-tasks.md brand/voice.md content/about-this-folder.md context/who-i-am.md context/who-i-serve.md offers/offers.md Leave every one of them empty except for a heading and a short bracketed placeholder telling me what belongs there. Do not ask me any questions. Do not write anything about my actual business. Do not guess at my voice, my offers, or my clients. I'm filling these in myself later. Two exceptions: CLAUDE.md also carries standing instructions for you, to be read at the start of every session: - Read the context and brand files before writing anything for me - Match my voice - Ask me before inventing any fact about my business - Push straight to main. Don't make branches or pull requests unless I ask for one. README.md explains in plain language what this repo is and how to use it, written for me six months from now when I've forgotten. Then create all of it and push straight to main.
Why the exact names matter. Everything you learn after this assumes the same layout. When a lesson says "put that in your brand folder," it has to mean one thing. Let Claude invent its own names and you'll be translating every instruction you ever read.
If it starts asking you questions anyway, tell it to stop and just make the empty files. There's a reason the prompt says it three different ways. An interview here turns a two minute step into twenty, and you'd be answering big questions about your voice and your clients cold, which is the worst moment to answer them.
One behavior that will surprise you. If Claude does ask something and you take a while to reply, the session may carry on without your answer and write the file anyway. Nothing is broken. Tell it what it got wrong and ask it to rewrite that file.
Want to skip the prompt entirely? The same structure exists as a template you can copy in one click: the Claude Code Starter Kit. Open it, hit Use this template, name it biz-brain, click Private. Same files, ten seconds. Running the prompt teaches you that Claude can build structure on command, which is worth knowing. The template is faster. Both land in the same place.
About branches, and why that rule appears twice. Branches and pull requests are a developer habit, built so a team of engineers doesn't write over each other. You're one person with notes about your own business, so they'd only add steps between you and your files.

Notice the rule is written in two places on purpose. The line at the bottom of the prompt applies to this conversation. The copy inside CLAUDE.md is the one that lasts, because that file gets read at the start of every session from now on. Telling Claude something once lives as long as the chat does. Writing it into CLAUDE.md makes it permanent. That difference is the entire reason you're building this folder.
Step Five

Fill the drawers

Empty folders do nothing. This is the step that turns a tidy structure into an assistant that knows you.

Two routes. Pick the one that's true for you.

Route one: you've been using Claude for a while

Then Claude already knows a lot about your business, and you'd be typing out things it could tell you. Get it out of the chat and into your files.

Open a normal Claude conversation, the regular chat and not Claude Code, and paste this:

You've been helping me with my business for a while. I'm building a permanent folder of files so you don't start from scratch every conversation. Using only what you actually know about me, write the contents of these four files: context/who-i-am.md My story. What I do, how I got here, what I did before this. context/who-i-serve.md My ideal client. Who they are, and what's going on for them when they find me. brand/voice.md How I sound. Phrases that are mine. Words and tones I'd never use. offers/offers.md What I sell. Name, price, and what's different for the person afterward. Important: - Use only what you genuinely know about me. Do not fill gaps with reasonable guesses. - Anywhere you don't actually know something, write [FILL IN] and move on. I would much rather have a visible gap than a sentence that sounds right and isn't true. - Write it in my voice where you can tell what my voice is. Give me all four in ONE single markdown block in your reply, with the filename as a heading above each section. Do not split them into separate documents, downloads, or attachments. I need to copy the whole thing in one go. After the files, in a few lines outside the block, tell me which of the four came out thin and what's actually missing from each. I want to know where to spend my time.

Copy the whole answer. Go back to Claude Code and paste it in with this:

If it hands you four separate documents to download instead of one block, just say "put all four into one markdown block in the chat so I can copy it" and it'll redo it.
File each of these into the matching files in this repo, replacing the placeholders. Then push to main.
Then read what it wrote. Every [FILL IN] is a real gap, and anything that isn't marked is something Claude believes about your business. Check the prices. Check the offer names. A wrong fact in here quietly becomes a wrong fact in everything it writes for you afterward.

Route two: you're new to Claude, or you'd rather start clean

Then nobody has the answers but you. Paste this into Claude Code and let it walk you through:

Read every file in this repo, starting with CLAUDE.md. Then interview me so we can fill in who-i-am, who-i-serve, voice, and offers. Ask one question at a time and wait for my answer before moving to the next. Keep it to about ten questions total. If I give you a thin answer, ask me a follow-up instead of accepting it. When we're done, write my answers into the right files, replacing the placeholders, and push to main.
One trick for the voice file. When it asks how you sound, don't describe yourself. Paste in three things you've actually written that felt like you, and let it work out the pattern. Describing your own voice is genuinely hard. Showing it is easy.

However you filled them, do this last: open a brand new conversation and ask it to write you something. It'll already sound like you, and you won't have explained a thing.

That's the whole point of the folder.

Step Six

Make the holes chase you

You will not have filled everything in. Nobody does. There are [FILL IN] markers scattered through those files right now, and left alone they'll still be there in March.

So don't rely on remembering. Build the reminder into the folder itself.

Go through every file in this repo and find every [FILL IN] marker and every open question left for me. Create a file at the root called open-questions.md: - Turn each gap into a plain question I can actually answer, not a label. "What does the Premium tier cost?" rather than "[FILL IN: price]". - Put the file it belongs in next to each question. - Use checkboxes so I can watch the list shrink. - Order them by how much they're holding back. The gaps that block the most of your future work go at the top. Add one line at the top explaining that order. Then add this standing rule to CLAUDE.md: At the start of every session, check open-questions.md. If anything is still unanswered, tell me how many are left and ask me exactly ONE of them, starting from the top. When I answer, write it into the right file, tick it off in open-questions.md, and then carry on with whatever I actually came in to do. Then push to main.
Why one question and not the list. A list of fourteen questions gets closed and ignored. One question gets answered in thirty seconds while you're already here for something else. Answer one a day and the whole thing is done in two weeks without ever sitting down to do it.
Why the order matters. A missing price breaks every sales email you'll ever ask for. A missing origin story breaks one about page. Same effort to answer, very different payoff, so the list puts the expensive gaps first.
This is the part that keeps working after you close the tab. Everything up to here was setup you did once. This is the folder getting better on its own, every time you come back, without you managing it.
